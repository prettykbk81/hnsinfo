# 앱 간 비교 분석

## 핵심 원칙

**"누가 이기고 있는가"를 한 문장으로 답하는 것이 목표다. 양쪽 다 좋다는 건 답이 아니다.**

비교 분석은 "각각의 현황 나열"이 아니라 "승패 판정"이다. 어떤 축에서 누가 이기고 있는지, 그 격차가 벌어지고 있는지 좁혀지고 있는지를 판단한다.

---

## 데이터 수집

**앱명 → 패키지명 변환:**
각 앱에 대해 `search_app(keyword: "앱명")`으로 패키지명 확인.

**비교 분석 호출:**
```
compare_competitors(pkgNames: "앱A,앱B,앱C", date: "현재월")
```

**추가 심화 (필요 시):**
```
app_health_check(pkgName: "각 앱", dateType: "m", startDate: "6개월 전", endDate: "현재")
```

## 분석 프로세스

### 1. 비교 축 설정

아래 축에서 각각 "누가 이기는지" 판정:

| 축 | 의미 | 데이터 |
|---|------|------|
| MAU | 규모 | ranking_users |
| 사용시간 | 습관/충성도 | ranking_time |
| 성장률 | 모멘텀 | 전월 대비 변화율 |
| 삭제율 | 마케팅 효율 | install_delete |
| 연령 분포 | 타겟 장악 | demographic |

### 2. 축별 승패 구분

각 축에서:
- 명확한 우위 (20%+ 차이) → "[A]가 압도적 우위"
- 근소한 우위 (5~20% 차이) → "[A]가 소폭 우위"
- 동등 (5% 이내) → "동등, 차별화 포인트 없음"

### 3. 격차 방향 판단

3~6개월 추이에서:
- 격차 벌어지는 중 → "A의 우위 강화"
- 격차 좁혀지는 중 → "B가 추격, 역전 가능성"
- 격차 유지 → "현 구도 고착"

### 4. 구조적 차이 발견

단순 수치 비교를 넘어:
- "왜 A가 이기는가?" — 전략/생태계/콘텐츠 차이
- "B가 역전하려면 뭘 해야 하는가?" — 구체적 조건

### 5. 웹서치로 맥락 보완

- 1차: "{앱A} vs {앱B} 비교 {해당 연도}"
- 2차: "{앱A} {앱B} 경쟁 동향 {해당 월}"
- 3차: "{앱A} 프로모션/신규 서비스 {해당 월}" + "{앱B} 프로모션/신규 서비스 {해당 월}"
- 최근 프로모션, 신규 서비스, 규제 변화 확인
- **각 앱의 최근 행보를 구체적으로 파악** — "왜 이 앱이 이기고 있는지"의 근거

### 6. 종합 결론

1. "현재 [A/B]가 우위. 핵심 차이는 [X]이다." — 한 문장
2. 축별 승패 요약 테이블
3. "역전 가능성: [높음/낮음]. 조건: [X]" — 미래 전망
4. 각 앱이 해야 할 것 — 구체적 액션

---

## 출력 규칙

- 첫 문장에서 "누가 이기고 있는지" 결론 (양비론 금지)
- 축별 승패를 테이블로 정리
- 격차 방향(벌어짐/좁혀짐)을 반드시 명시
- "둘 다 좋다"는 답 금지. 반드시 우열을 가린다
- 데이터 없으면 추측 금지
- "판정", "판단" 같은 딱딱한 워딩 쓰지 않는다
- `suggested_searches`가 있으면 반드시 웹서치 실행

## 업종 맥락 참조

비교 대상 앱의 업종에 해당하는 `industry/` 파일을 참조하여 업종 특화 비교 축을 추가한다.
예: 배달앱 비교 시 → `industry/delivery.md`의 "격차 변화 속도", "무료배달 효과" 추가 적용.
